# 청약 블로그 발행 가이드 — 네이버 SEO 기준

조사일: 2026-10-12 · 다음 확인: 2027-01 (분기마다, 네이버 검색 공지가 나오면 바로)

원고 메일 한 통을 네이버 블로그 글 한 편으로 올릴 때 위에서부터 따라가는 문서다.
단계마다 **규칙 → 이미 됨(프로그램이 해 둔 것) → 직접 할 것** 순서로 적었다.

## 근거 표시

| 표시 | 뜻 |
|---|---|
| **[공식]** | 네이버 보도자료·공식 발표 |
| **[보도]** | 언론 기사에 실린 네이버 관계자 발언·발표 |
| **[업계]** | 마케팅 업체·블로거·위키 주장. 네이버가 확인한 적 없음 |
| **[확인 필요]** | 근거를 찾지 못함. 글쓰기 화면이나 고객센터에서 직접 확인 |

네이버는 검색 순위 규칙을 거의 공개하지 않는다. 이 문서의 **[업계]** 항목은 "해서 손해 볼 일은 없는 것" 위주로만 골랐다.

---

## 0. 3분 요약

**발행 순서**: 제목 → 썸네일 → 본문 붙여넣기 → 태그 → 카테고리 → 예약 발행

**꼭 지킬 것**
1. 메일 위 노란 상자의 제목·태그·예약 시각을 그대로 쓴다.
2. 썸네일 카드가 글의 첫 이미지인지 확인한다.
3. 검증 메모 칸이 빨간색이면 그 공고를 공고문으로 확인한 뒤 올린다.
4. 인물마다 정해진 카테고리에 올린다.
5. 월·수·금을 거르지 않는다.

**하지 말 것**
1. 같은 원고를 두 번 올리거나 다른 블로그에 똑같이 올리기
2. 원고 여러 편을 같은 시각에 몰아서 즉시 발행하기
3. "가상 인물"·"판정은 참고용" 안내 문구 지우기

---

## 1단계. 제목

**규칙**
- 사람들이 검색하는 단어(단지명·전형)를 제목 앞쪽에 둔다. **[업계]**
- 같은 단어 반복, "역대급"·"무조건" 같은 과장·낚시성 표현은 중복·저품질로 읽히기 쉽다. **[업계]**

**이미 됨**
- `단지명 + 특공 이름(없으면 청약) 자격 — 인물 기준 새 공고 N건 (날짜)` 형식으로 자동 생성
  - 예: `더샵 오산역아크시티 오피스텔 청약 자격 — 두 자녀 가구 기준 새 공고 5건 (10/12)`

**직접 할 것**
- 노란 상자의 **제목**을 복사해 제목란에 붙인다.

| 고쳐도 됨 | 고치면 안 됨 |
|---|---|
| 단지명 오타·띄어쓰기 수정 | "무조건 당첨", "역대급 기회" 같은 과장 추가 |
| 공고명이 너무 길 때 뒷부분 줄이기 | 단지명을 빼고 "오늘의 청약"처럼 일반 제목으로 바꾸기 |

---

## 2단계. 대표 이미지(썸네일)

**규칙**
- 글의 첫 이미지가 검색 결과·목록의 썸네일이 된다. **[업계]**
- PC 목록은 3:2, 모바일은 1:1로 잘린다고 알려져 있다. 핵심 글자는 가운데에 둔다. **[업계]**

**이미 됨**
- 1080×1080 카드를 본문 맨 위에 배치 (`src/thumbnail.py`)
  - 파란 띠: 모델 번호 · 인물 이름 · 가족 아이콘 · 기준일
  - 큰 제목 "이 청약 넣을 수 있어요", 조건 체크 3줄, "신청 가능"(❔ 판정이면 "확인 필요") 도장
  - 검은 띠: 마감이 가장 빠른 단지 · D-day

**직접 할 것**
- 복사한 본문 속 이미지는 네이버에 사진으로 올라가지 않는다. Gmail 로그인 전용 주소나 파일로 붙어 PC에서만 보이고 모바일 앱·다른 방문자에게는 "존재하지 않는 이미지"로 나온다(2026-10-13 확인). 사진 파일·캡처를 직접 넣으면 올라간다.
- 그래서 원고 본문에는 이미지 대신 **📷 사진 넣을 자리** 표시가 있다. 자리마다 첨부 `01_썸네일.png`, `02_시세그래프_….png` … 를 사진 버튼으로 넣고 표시 줄을 지운다.
- 붙여넣은 뒤 썸네일 카드가 **첫 이미지**인지 확인한다.
- 에디터에서 대표 이미지로 지정됐는지 확인한다.

## 3단계. 본문

**규칙**
- AI 브리핑은 검색 답변과 함께 근거가 된 블로그 글을 출처로 보여 준다. **[공식]**
- AI 브리핑에 인용된 글의 약 70%가 블로그·카페 같은 네이버 이용자 글이다. **[보도]**
- 출처가 분명하거나 직접 경험한 글이 더 노출되도록 알고리즘을 조정하고 있다. **[보도]**
- 키워드 반복보다 정보의 완성도와 구조(소제목·표), 최신성이 중요해졌다. **[업계]**
- AI로 썼다는 이유만으로 검색에서 빼는 공식 규칙은 확인되지 않는다. 기계적으로 대량 생산한 글이 문제다. **[업계]**

**이미 됨**
- 청약홈·LH 공공데이터로 판정한 내용(검증 가능한 정보)
- 원고마다 달라지는 도입부 2~4문장 (여는 문장 3가지를 인물·날짜로 돌려 씀)
- 공고 카드는 표 대신 문단, 요약표는 1개만 (네이버 에디터에서 표 너비가 깨지는 문제)
- 오늘 마감 공고 제외
- 의심스러운 시세(다른 시·도에서 잡힘, 차이 ±80% 초과)는 글에서 자동 삭제
- 맞춤법 자동 검사: 단지명 뒤 조사(으로/로·은/는·이/가·을/를·과/와)를 받침에 맞춰 붙이고, 발송 전에 조사 오류·같은 단어 반복·문장부호 앞 공백·빈 괄호·흔한 오기(됬·몇일·할께 등)를 찾아 검증 메모에 적음
- 맨 끝 "가상 인물 · 판정은 참고용" 안내와 #해시태그 줄

**직접 할 것**
- 노란 상자 아래 빨간 안내선부터 끝까지 복사해 붙인다. 📷 자리에 첨부 사진을 넣는다(2단계).
- **검증 메모가 빨간색이면** 적힌 공고를 공고문으로 확인한다. 틀린 내용이면 그 부분을 지우고 올린다.
- 표·이미지·링크가 깨진 곳이 없는지 훑어본다.
- 스마트에디터의 **맞춤법 검사**를 한 번 돌린다. 프로그램은 자기가 만든 문장(조사·반복 단어·공백·흔한 오기)만 검사하고, 직접 덧붙인 문장은 검사하지 못한다.
- (선택) 도입부 아래에 직접 쓴 한두 문장을 더한다. 직접 쓴 문장은 같은 틀의 글끼리 겹치는 부분을 줄인다.
  - "이 인물이라면 저는 ○○부터 넣겠어요. 마감이 가장 빠르고 통장이 없어도 되거든요."
  - "○○은 시세보다 비싸게 나왔지만 역에서 도보 9분이라 실거주라면 볼 만합니다."
  - "이번 주는 신혼부부 특공 물량이 많았어요. 혼인 7년 안쪽이라면 놓치지 마세요."

## 4단계. 태그

**규칙**
- 태그 개수 공식 기준은 찾지 못했다. 본문 해시태그는 최대 30개라는 설명이 있다(2년 전 글). **[확인 필요]**
- 글과 관계없는 인기 키워드를 끼워 넣지 않는다. **[업계]**

**이미 됨**
- 인물 고정 태그 6개 + 이번 글의 단지명 · 동네청약(예: 부천청약) · 전형 · N월청약, 최대 20개
- 노란 상자에 쉼표로 구분한 목록, 본문 끝에 #해시태그 줄

**직접 할 것**
- 노란 상자의 **태그** 목록을 태그 칸에 붙인다. 하나로 뭉치면 하나씩 입력한다.
- 태그 칸 개수 제한에 걸리면 뒤쪽(N월청약·청약공고 등)부터 뺀다.

---

## 5단계. 카테고리·발행

**규칙**
- 한 주제를 꾸준히 다루는 블로그가 유리하다(C-Rank의 주제 전문성). **[업계]**
- 짧은 시간에 여러 편을 몰아 올리는 것은 도배로 보일 수 있다. **[보도]** (도배는 제재 대상)

**이미 됨**
- 한 번에 최대 3편, 가장 오래 글이 안 나간 인물부터
- 예약 시각을 나가는 순서대로 08:30 · 12:30 · 19:30으로 지정

**직접 할 것**
- 메일의 **카테고리**를 고른다.
- 메일의 **예약 발행** 시각으로 예약한다. 즉시 발행하지 않는다.
- 월·수·금 원고는 그날 안에 예약까지 마친다.

## 6. 하지 말 것 (계정 제재 위험)

| 하지 말 것 | 이유 | 근거 |
|---|---|---|
| 광고·스팸·도배·매크로 | 네이버가 어뷰징으로 제재한다고 밝힘 | **[보도]** |
| 같은 원고를 다시 올리거나 다른 블로그에 똑같이 게시 | 유사 문서로 노출 불이익 | **[업계]** |
| 원고 여러 편 동시 즉시 발행 | 도배로 보일 수 있음 | **[보도]** |
| 안내 문구(가상 인물·참고용) 삭제 | 실제 인물·확정 판정으로 오해될 수 있음 | 운영 원칙 |
| 외부 프로그램으로 자동 발행 | 자동화 프로그램 이용은 제한 대상으로 알려짐 | **[업계]** |

> **자동 발행(NAS 계획) 메모**: 처음 계획은 NAS에서 Playwright로 예약 발행까지 자동화하는 것이었다.
> 위 "매크로 제재" 발언 때문에, 실행 전에 계정 위험을 다시 따져 보고 결정한다.
> 그 전까지는 지금처럼 메일 원고를 받아 직접 붙여넣고 예약한다.

## 7. 조회수를 더 늘리는 다음 단계 — 나중에 적용

> **상태: 보류.** 아래는 지금 원고에는 들어가 있지 않다. 적용할 때 항목별로 이 표의 상태를 바꾼다.

| 항목 | 내용 | 필요한 작업 | 상태 |
|---|---|---|---|
| 경쟁률·당첨 가점 후속 글 | 앞서 다룬 단지의 경쟁률·당첨 가점을 발표 직후 정리. "단지명 경쟁률"은 검색 의도가 분명함 | 청약홈 경쟁률·당첨 API 수집, 후속 원고 틀 | 보류 |
| 카테고리 소개 고정 글 | 인물 카테고리마다 "이 인물은 누구이고 어떤 공고를 다루는지" 글 하나 | 소개 글 11편 직접 작성 (원고 초안은 요청하면 생성) | 보류 |
| 청약 카페·오픈채팅 공유 | 초기 유입 확보 | 카페별 홍보 규정 확인 후 직접 공유 | 보류 |

적용 순서 제안: 카테고리 소개 글 → 경쟁률 후속 글 → 공유.
소개 글은 손이 적게 들고, 후속 글은 효과가 크지만 프로그램 작업이 필요하다.

## 8. 발행 전 1분 점검표

- [ ] 제목: 노란 상자 제목 복사, 과장 표현 없음
- [ ] 썸네일: 카드가 첫 이미지, 대표 이미지로 지정됨
- [ ] 검증 메모: "없음"이거나, 빨간 칸이면 공고문 확인 끝냄
- [ ] 본문: 표·이미지·링크 깨짐 없음
- [ ] 맞춤법: 붙여넣은 뒤 에디터의 맞춤법 검사 한 번 (직접 덧붙인 문장 포함)
- [ ] 사진: 📷 자리마다 첨부 사진을 넣고 자리 표시 줄을 모두 지움
- [ ] 이미지: 발행 후 휴대폰 네이버 앱에서 썸네일·그래프가 보이는지 확인
- [ ] 안내 문구: "가상 인물 · 판정은 참고용"이 맨 끝에 남아 있음
- [ ] 태그: 붙여넣음, 관계없는 키워드 없음
- [ ] 카테고리: 인물 카테고리 선택
- [ ] 예약: 메일의 예약 시각으로 예약 (즉시 발행 아님)
