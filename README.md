# 청약 블로그 원고 생성기

가상 인물 11명(`profiles/*.yaml`)마다 지원할 수 있는 청약홈 분양·LH 임대 공고를 골라
네이버 블로그 원고를 만들어 메일로 보낸다. 월·수·금 06:00(KST), 인물 한 명당 글 한 편.
한 번에 **최대 3편**(`--max`, 시크릿/변수 `BLOG_DAILY_MAX`)이고, 가장 오래 글이 안 나간 인물부터 채운다.
못 나간 인물의 새 공고는 기록이 남지 않아 다음 발행일로 넘어간다. 예약 시각은 나가는 순서대로 08:30·12:30·19:30.

- 판정·수집 코드는 청약 알리미 베타(`cheongyak-alert-beta`)에서 복사했다. 베타와 따로 운용한다.
- 지난 원고 뒤로 **새 공고가 없는 인물은 건너뛴다.** 새 공고는 최대 6건(분양·임대 반씩)만
  자세히 쓰고, 나머지는 '계속 접수 중' 목록에 한 줄씩 적는다. 자세히 쓰지 못한 새 공고는 다음 원고에서 자세히 쓴다.
- 인물은 직장이 없어 통근시간을 계산하지 않는다(ODsay 미사용).
- **같은 공고는 한 인물에게만** 간다. 실행마다 전원의 후보 공고를 먼저 모으고(`gather`), 아직 어느 인물로도
  안 나간 공고마다 가장 알맞은 인물 하나를 정한다(`assign`): 특공(임대는 청년·신혼·고령자 등 대상 유형) >
  일반공급 > 누구나 넣는 공고, ✅ > ❔, 사는 시·도 가산, 같으면 후보가 적은 인물 → 오래 안 나간 인물.
  이미 어느 인물로든 나간 공고는 다른 인물에게 다시 넣지 않고, '계속 접수 중' 목록도 그 공고를 처음 쓴 인물에게만 둔다.
- 인물 파일은 실존 인물이 아니므로 저장소에 커밋한다.
- 상세 자리는 특공·일반공급 공고에 먼저 준다. 임의공급·무순위처럼 누구나 넣는 공고는 뒤로 민다.
- 베타 메일 형식을 그대로 쓰되 통근 칸은 뺐고, 신청 방법에 ❔(공고문 확인 필요)도 함께 싣는다.
- 네이버 에디터가 붙여넣은 표의 너비를 깨뜨려, 맨 위 요약표만 표로 두고 공고 카드·LH 임대 목록은 문단으로 쓴다.
- 제목은 검색어가 앞에 오도록 '단지명 + 특공 이름(없으면 청약) 자격 — 인물 기준 새 공고 N건 (날짜)'.
- 글 맨 위에 대표 이미지(썸네일 카드, `src/thumbnail.py`)와 원고마다 달라지는 도입부 2~4문장을 넣는다. 썸네일은 한글 글꼴이 있어야 해 Actions 에서 fonts-nanum 을 설치한다.
- 오늘 마감 공고는 넣지 않는다(글이 08:30 이후에 올라가 신청할 시간이 없다).
- 공개 글이라 의심스러운 시세는 메모만 남기지 않고 글에서 뺀다: 시세를 잰 지역이 공급지역 시·도가 아니거나, 시세·주변 분양가 차이가 80% 초과면 그 비교를 지우고 검증 메모(빨간 칸)에 적는다. 위치를 못 찾은 공고도 메모에 남는다.
- `--test`: 제목에 [시험]을 붙여 보내고 발송 이력은 남기지 않는다.
- 태그는 인물 고정 태그 6개 + 이번 글의 단지명·동네청약·전형·N월청약, 최대 20개. 메일 위 칸은 쉼표 구분(태그 입력란용), 본문 끝에는 #해시태그 줄이 함께 복사된다.

## 원고 메일 쓰는 법 (반자동)

발행 단계별 규칙과 점검표는 [docs/naver-seo.md](docs/naver-seo.md) 를 따른다.

1. 메일 위쪽 노란 상자에서 **카테고리·제목·태그·예약 발행 시각**을 확인한다.
2. 빨간 안내 아래 선부터 끝까지 복사해 네이버 스마트에디터에 붙여 넣는다.
3. 그래프가 빠지면 메일의 그래프 이미지를 저장해 넣는다.
4. 카테고리를 고르고 예약 발행 시각을 맞춰 발행한다.

검증 메모가 '없음'이 아니면 붙여 넣기 전에 그 공고를 공고문으로 확인한다.

## 실행

```
python -m src.main --preview preview          # 메일 대신 preview/<별칭>.html (이력 안 남김)
python -m src.main --only p1-youth            # 한 명만 실제 발송
SELFTEST=1 python -m src.main                 # 자체 점검
```

GitHub 시크릿: `ODCLOUD_SERVICE_KEY`, `KAKAO_REST_API_KEY`, `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `BLOG_TO`(선택).

## 인물 바꾸기

`profiles/<별칭>.yaml` 의 `blog:` 블록이 글에 나가는 소개다(카테고리·라벨·소개·요약·태그).
나머지 항목은 베타 프로필 양식과 같고, 블로그용으로 `minor_children`(미성년 자녀 수), `youngest_child_birth`(막내 생일), `pregnant`, `elder_parent_65`(함께 사는 부모 65세 이상)를 더 읽는다. 바꾼 뒤 `data/seen/<별칭>.json` 을 지우면 처음부터 다시 쓴다.
